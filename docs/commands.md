# Commands

Every command has the same shape: `hive [global flags] <command> [flags] [args]`. The global flags are `--home`, `--project`, `--agent`, `--session`, `--json`, `--quiet`, `--no-color` and `--now`. The variables `$HIVE_HOME`, `$HIVE_PROJECT`, `$HIVE_AGENT`, `$HIVE_SESSION` and `$HIVE_NOW` set the defaults of `--home`, `--project`, `--agent`, `--session` and `--now`; without `$HIVE_HOME` the store lives in `~/.hive`.

Run `hive help` for this list and `hive help <command>` for the text shown under each command. The help writes each flag with one dash (`-json`); you can type two (`--json`), as the usage lines do. The settings have a page of their own: [Settings](settings.md).

This page is generated by `scripts/gen-reference.sh` from what `hive help` and `hive help <command>` print. Do not edit it by hand: change the help text in the code, then run the script again.

## Agents - the board

### agent

Join with a unique name, spawn a worker, list, beat, or prune.

```text
hive agent  join with a unique name, spawn a worker, list, beat, or prune

Usage: hive agent join --name NAME [--runner R] [--model M] [--session S] [--display D] [--kind session|worker]
       hive agent spawn [--runner R] [--model M]
       hive agent list [--all] [--json]
       hive agent beat [--name NAME] [--json]        (a sign of life; silent agents are dead after heartbeat.dead_after)
       hive agent prune [--days N] [--dry-run] [--now T]
       (`hive agent` manages the running workers; `hive agents` their definitions)

Flags:
  -all
        include pruned agents (list)
  -days int
        prune after this many days without useful output (default: setting prune_after_days) (default -1)
  -display string
        a display name (join)
  -dry-run
        prune: report only
  -kind string
        session or worker (join) (default "session")
  -model string
        the model behind the agent (join, spawn)
  -name string
        the agent's unique name (join, beat)
  -runner string
        the runner the agent runs in (join, spawn)
```

### mcp

MCP servers agents can call: add, list, show, update, enable, disable, login, logout, connect, tools, call, resources, read.

```text
hive mcp  MCP servers agents can call: add, list, show, update, enable, disable, login, logout, connect, tools, call, resources, read

Usage: hive mcp add --name N --transport stdio|http|sse (--command CMD [--arg A]... | --url U) [--auth none|bearer|basic|header|query|env|oauth] [--auth-header NAME] [--secret REF] [--env K=V]... [--project P] [--note TEXT]
hive mcp list [--project P] [--json]
hive mcp show N|MCP-NNN [--json]
hive mcp update N|MCP-NNN [--name N] [--transport T] [--command CMD] [--arg A]... [--url U] [--auth A] [--auth-header NAME] [--secret REF] [--env K=V]... [--note TEXT] [--project P]
hive mcp enable|disable N|MCP-NNN
hive mcp login N [--client-id ID [--client-secret REF]] [--flow code|device] [--scope S] [--redirect-port N] [--no-browser] [--json]   (auth oauth: sign in once, in a browser or with a code)
hive mcp logout N [--json]               (auth oauth: revoke and forget the tokens)
hive mcp connect N [--json]              (initialize + tools/list; records the check)
hive mcp tools N [--json]
hive mcp call N TOOL [--args JSON | stdin] [--json]   (exit 1 when the tool reports an error)
hive mcp resources N [--json]
hive mcp read N URI [--json]

The secret is a hive_cred reference, never the value: op://VAULT/ITEM/FIELD, keychain://SERVICE/ACCOUNT or file:///ABSOLUTE/PATH. For basic auth it resolves to user:password. Env values may be references too.

auth oauth (http, sse) takes no secret: hive mcp login N finds the server's authorization server, registers Hive as a client when the server allows it, signs in through your browser (OAuth 2.1, PKCE) and keeps the tokens in ~/.hive/secrets/mcp-oauth/, refreshing them itself. A provider that registers no clients (GitHub) signs in through a public client Hive carries - the GitHub CLI's app, the one github-models uses - with the device flow: Hive shows a code to type on github.com, where the page asks you to authorize GitHub CLI; nothing to register. --client-id and --client-secret are for a client you registered with the provider by hand instead; --redirect-port fixes the loopback port such a client was registered with. When the provider offers the device flow (RFC 8628) your client needs no secret and no port (--flow device, the default for such a client). The hub's Connections page runs the same sign-in from the browser.

A server is for every project unless --project P names the one project that may use it; the project of your shell (HIVE_PROJECT) does not narrow it. A project's own server replaces a shared one with the same name.

Flags:
  -arg argument
        stdio: one argument of the command; repeat for more (update: --arg '' clears them)
  -args string
        call: the tool's arguments as a JSON object (or on stdin)
  -auth string
        none, bearer, basic, header, query, env or oauth (add, update; default none)
  -auth-header string
        the header, query parameter or env var that carries the secret (header, query, env)
  -client-id id
        login: a client id you registered with the provider by hand (default: Hive registers itself, or signs in through its built-in client where the provider registers none)
  -client-secret reference
        login: that client's secret as a hive_cred reference, when it has one
  -command string
        stdio: the program to run (add, update)
  -env K=V
        stdio: K=V for the command's environment; V may be a hive_cred reference; repeat for more (update: --env '' clears them)
  -flow code
        login: code (a browser redirect) or `device` (a code typed on the provider's page; needs --client-id or a built-in client) (default: device when the client is yours or built in and the server offers it, else code)
  -name string
        the server's name, a slug (add, update)
  -no-browser
        login: print the sign-in address, do not open a browser
  -note string
        what the server is for; agents read it (add, update)
  -project string
        the one project that may use the server (add, update; default: every project, whatever HIVE_PROJECT says)
  -redirect-port port
        login: the loopback port the redirect URI uses (default: one the system picks)
  -scope scopes
        login: the scopes to ask for, space-separated (default: what the server suggests)
  -secret reference
        a hive_cred reference to the secret (every auth but none)
  -transport string
        stdio, http or sse (add, update)
  -url string
        http, sse: the server's address (add, update)
```

### schedule

A standing job for a project - queued again every cadence - or a check/watch script the daemon runs without an LLM: add, list, show, log, pause, resume, end, run.

```text

  -brief-file string

  -every string

  -job-kind string
        check/watch: the kind of job a red check or a firing watch queues, task (default) or improve (add)
  -kind string
        task, improve, clean or reflect (a job every cadence); check or watch (a script, --script) (add) (default "task")
  -note string
        why (pause, end)
  -priority int
        priority, higher first (add)
  -run-as string
        the custom agent every job it queues runs as, one that hive agents list shows for the project (add)
  -script string
        check/watch: the script to run, relative to the repo root, committed on the default branch (add)
  -skill string

  -status string
        list only active, paused or ended schedules
  -tier int

  -times int
```
